# 问否：首版架构与交付路线

## 产品边界

问否让用户先在私密会话中提问，再主动选取问题与回答片段，预览、确认并提交审核，审核通过后形成公开的不可变快照。读者可以从公开快照开始自己的私密追问。公开内容须标识为 AI 生成；用户补充的分享理由与模型回答分别展示。

首版以中国市场 Android 客户端为入口。微信小程序复用相同的服务端 API 与内容规则，在 Android 完成账户、回答、发布、审核和撤回的闭环后接入。当前代码是可打开的 Android 本地界面原型与可运行的领域逻辑，尚未实现联网产品。

## 数据与隐私边界

`conversations` 按 `owner_id` 隔离，`messages` 隶属会话。`posts` 单独保存用户选取的问题、回答片段和分享理由，状态依次为 `pending`、`published`、`rejected` 或 `withdrawn`。公开接口仅返回 `published` 快照；分叉只复制公开快照，不读取原作者私聊。撤回后公开读取与分叉均失效，既有读者私密分叉需另定删除与通知策略。

HTTP 层必须从已验证令牌导出内部用户 ID，不接受客户端传入的任意 `owner_id`。运营审核动作必须单独授权并记审计日志；当前 `review_post` 只是受信调用端的领域方法，不能直接暴露给普通用户。发布前应明确展示会公开的完整片段，并支持识别手机号等个人信息的提示与人工修正。

## Android 首版闭环

1. 登录与账户：选定合规的登录方式，建立令牌与用户数据删除流程。
2. 私密提问：通过后端生成回答，逐条保存会话与模型运行状态；失败可重试。
3. 主动分享：用户选段、填写理由、预览、确认；服务器验证片段归属，转入待审核。
4. 审核与发现：运营审核后进入公开流，支持详情、举报、撤回和 AI 内容标识。
5. 私密追问：读者从公开快照复制自己的会话，后续内容默认私密。

完成上述真实 API 与 Android 真机验收后，微信小程序接入相同 API，并处理微信授权、分享卡片与小程序特有的审核要求。客户端不持有模型密钥。

## 接口与部署

接口草案见 `contracts/api-draft.yaml`。流式事件、错误码、游标分页、举报、撤回、运营审核、内容安全、账户删除、模型来源及引用信息还需细化。生产环境建议将领域存储迁移到 PostgreSQL，模型任务使用队列与超时控制，附件置于对象存储；网关承担速率限制与滥用防护。中国市场上线前，应按实际模型供应商、内容形态与业务主体完成相应的合规核查。

## 本切片验收

- `cd server && python3 -m unittest discover -s tests -v`：验证私聊隔离、未审核不可公开、选段归属、公开分叉隔离与撤回。
- `cd clients/android && bash gradlew :app:assembleDebug`：需要 JDK 17、Android SDK 36 和依赖下载；CI 执行同一构建并上传 debug APK。
- 手工检查四个 Android 页面、空问题按钮状态、样例回答标识、发布预览。当前发布按钮不会发起网络请求。
